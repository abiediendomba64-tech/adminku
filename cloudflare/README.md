## Google Search Console API via Telegram

The Worker uses **Google Search Console API** (OAuth 2.0), not Google Indexing API. The API integration is intentionally limited to properties that the OAuth Google account can already access.

### One-time setup

1. Verify the website in Search Console. For verification without DNS access, use a **URL-prefix property** (for example, `https://mami44.com/`) and the HTML meta-tag method. Add the exact tag generated by Search Console to the website's public `<head>` through its Marketing Tags panel, save it, then click Verify in Search Console. The tag must be present on the matching public website.
2. In Google Cloud Console, create/select the project and enable **Google Search Console API**.
3. Create an OAuth 2.0 client and obtain an offline refresh token for the Google account that has access to the Search Console property. Grant the scope `https://www.googleapis.com/auth/webmasters` (read/write; required for sitemap submission). OAuth must request offline access so the refresh token can be used by the Worker without repeated interactive login.
4. Add these three values as **Production Runtime Secrets** on the Cloudflare Worker. Do not put them in GitHub, `wrangler.toml`, Android preferences, or chat:
   - `GSC_CLIENT_ID`
   - `GSC_CLIENT_SECRET`
   - `GSC_REFRESH_TOKEN`
5. Keep the OAuth client and refresh token under the control of the site owner. If access is revoked, the token is invalidated, or the refresh token expires, authorize again and replace the Runtime Secret.

Google OAuth reference: https://developers.google.com/identity/protocols/oauth2/web-server  
Search Console API reference: https://developers.google.com/webmaster-tools/v1/api_reference_index

### Admin Telegram commands

All commands below are restricted to configured Telegram admin IDs:

- `/gsc_test` — refresh OAuth access token and call Search Console `sites.list`.
- `/gsc_sites` — list properties visible to the OAuth account.
- `/gsc_inspect https://mami44.com/page` — inspect an indexed URL. Optional second argument chooses the exact property, for example `/gsc_inspect https://mami44.com/page https://mami44.com/` or `/gsc_inspect https://mami44.com/page sc-domain:mami44.com`.
- `/gsc_sitemaps https://mami44.com/` — list sitemaps for a property. Use the exact property URL shown by `/gsc_sites`.
- `/gsc_submit_sitemap https://mami44.com/ https://mami44.com/sitemap.xml` — submit a sitemap to Search Console.

### D1 logging and important behavior

URL inspection and sitemap submission use the existing `gsc_submission_logs` columns: `url`, `domain`, `searchEngine`, `httpStatus`, `verificationTagFound`, `sitemapDetected`, `indexingStatus`, `diagnosticMessage`, `gscTrackingId`, and `submittedAt`. No schema migration is required for these commands.

A successful sitemap API response means Google accepted the sitemap submission; it does **not** guarantee that URLs are crawled or indexed. URL Inspection reads the status of the URL currently known to Google's index. Search Console API does not provide the ordinary URL Inspection UI's **Request Indexing** action for arbitrary pages. The legacy `/reindex` command is a local HTTP/meta/sitemap audit only and must not be interpreted as a Google indexing request.
